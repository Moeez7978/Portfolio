11:T8a9f,<h1><img src="https://upload.wikimedia.org/wikipedia/commons/9/93/Amazon_Web_Services_Logo.svg" width="40" align="center"/> AWS CloudFormation — Complete Guide for AWS Solutions Architect Associate</h1>
<blockquote>
<p><strong>AWS CloudFormation</strong> is AWS's Infrastructure as Code (IaC) service that lets you model, provision, and manage AWS and third-party resources by treating infrastructure as code — declaratively, repeatably, and safely.</p>
</blockquote>
<hr>
<h2>📐 Architecture &#x26; Infrastructure</h2>
<p align="center">
  <img src="https://raw.githubusercontent.com/acantril/aws-sa-associate-saac03/main/2100-IAC_CLOUDFORMATION/00_LEARNINGAIDS/Physical-and-Logical-Resources-1.png" width="750"/>
</p>
<p align="center">
  <img src="https://raw.githubusercontent.com/acantril/aws-sa-associate-saac03/main/2100-IAC_CLOUDFORMATION/00_LEARNINGAIDS/Physical-and-Logical-Resources-2.png" width="750"/>
</p>
<h3>How CloudFormation Works — The Big Picture</h3>
<pre><code>Developer writes Template (JSON/YAML)
          │
          ▼
   CloudFormation Service
          │
    ┌─────┴──────┐
    │  Template   │  ← Parsed, validated, dependency-resolved
    │  Engine     │
    └─────┬──────┘
          │
    ┌─────▼──────────────────────────────────┐
    │              Stack                      │
    │  (Logical grouping of AWS resources)    │
    └─────┬──────────────────────────────────┘
          │
    ┌─────▼──────────────────────────────────┐
    │         Provisioned Resources           │
    │  EC2 | S3 | RDS | VPC | IAM | Lambda   │
    └────────────────────────────────────────┘
</code></pre>
<p>CloudFormation reads your template, builds a dependency graph, and provisions resources in the correct order — automatically handling creation, updates, and deletion as a single atomic unit.</p>
<h3>Core Concepts</h3>
<table>
<thead>
<tr>
<th>Concept</th>
<th>Description</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>Template</strong></td>
<td>JSON or YAML file describing the desired infrastructure state.</td>
</tr>
<tr>
<td><strong>Stack</strong></td>
<td>A deployed instance of a template. All resources in a stack are managed together.</td>
</tr>
<tr>
<td><strong>Change Set</strong></td>
<td>A preview of proposed changes before applying an update to a stack.</td>
</tr>
<tr>
<td><strong>Stack Set</strong></td>
<td>Deploy stacks across multiple AWS accounts and regions from a single operation.</td>
</tr>
<tr>
<td><strong>Drift</strong></td>
<td>When a resource's actual configuration differs from what CloudFormation expects.</td>
</tr>
<tr>
<td><strong>Nested Stack</strong></td>
<td>A stack created as a resource within another (parent) stack.</td>
</tr>
</tbody>
</table>
<hr>
<h2>🧱 Template Anatomy</h2>
<p>A CloudFormation template has up to 10 sections. Only <code>Resources</code> is mandatory.</p>
<pre><code class="language-yaml">AWSTemplateFormatVersion: "2010-09-09"   # Optional — always this value if used

Description: "My CloudFormation Template"  # Optional — string description

Metadata:                                  # Optional — additional info for tools/console
  AWS::CloudFormation::Interface:
    ParameterGroups: [...]

Parameters:                                # Optional — dynamic inputs at deploy time
  EnvironmentType:
    Type: String
    AllowedValues: [dev, staging, prod]
    Default: dev

Mappings:                                  # Optional — static lookup tables
  RegionAMIMap:
    us-east-1:
      AMI: ami-0abcdef1234567890

Conditions:                                # Optional — conditional resource creation
  IsProd: !Equals [!Ref EnvironmentType, prod]

Transform:                                 # Optional — macros (e.g., SAM transform)
  - AWS::Serverless-2016-10-31

Resources:                                 # REQUIRED — the actual AWS resources
  MyBucket:
    Type: AWS::S3::Bucket
    Properties:
      BucketName: my-app-bucket

Outputs:                                   # Optional — values to export or display
  BucketName:
    Value: !Ref MyBucket
    Export:
      Name: MyAppBucketName
</code></pre>

<h2>⚙️ How CloudFormation Operates</h2>
<h3>Stack Lifecycle</h3>
<pre><code>Template Submitted
       │
       ▼
  REVIEW_IN_PROGRESS
       │
       ▼
  CREATE_IN_PROGRESS  ──► CREATE_FAILED ──► ROLLBACK_IN_PROGRESS ──► ROLLBACK_COMPLETE
       │
       ▼
  CREATE_COMPLETE
       │
       ▼
  UPDATE_IN_PROGRESS  ──► UPDATE_FAILED ──► UPDATE_ROLLBACK_IN_PROGRESS
       │
       ▼
  UPDATE_COMPLETE
       │
       ▼
  DELETE_IN_PROGRESS  ──► DELETE_FAILED
       │
       ▼
  DELETE_COMPLETE
</code></pre>
<h3>Resource Provisioning Order</h3>
<p align="center">
  <img src="https://raw.githubusercontent.com/acantril/aws-sa-associate-saac03/main/2100-IAC_CLOUDFORMATION/00_LEARNINGAIDS/CloudFormationDependsOn.png" width="750"/>
</p>
<p>CloudFormation builds an internal dependency graph using <code>DependsOn</code> and intrinsic function references (<code>!Ref</code>, <code>!GetAtt</code>). Resources with no dependencies are provisioned in parallel; dependent resources wait.</p>
<pre><code class="language-yaml">Resources:
  MyVPC:
    Type: AWS::EC2::VPC
    Properties:
      CidrBlock: 10.0.0.0/16

  MySubnet:
    Type: AWS::EC2::Subnet
    Properties:
      VpcId: !Ref MyVPC          # ← CloudFormation knows Subnet depends on VPC
      CidrBlock: 10.0.1.0/24
</code></pre>
<h3>Rollback Behavior</h3>
<table>
<thead>
<tr>
<th>Scenario</th>
<th>Default Behavior</th>
</tr>
</thead>
<tbody>
<tr>
<td>Stack creation fails</td>
<td>Entire stack rolls back and all resources are deleted</td>
</tr>
<tr>
<td>Stack update fails</td>
<td>Rolls back to the last known good state</td>
</tr>
<tr>
<td>Rollback itself fails</td>
<td>Stack enters <code>UPDATE_ROLLBACK_FAILED</code> — requires manual intervention</td>
</tr>
</tbody>
</table>
<blockquote>
<p>💡 <strong>Tip:</strong> You can disable rollback on creation failure (useful for debugging) using <code>--disable-rollback</code> in the CLI.</p>
</blockquote>

<h2>🔧 Parameters</h2>
<p align="center">
  <img src="https://raw.githubusercontent.com/acantril/aws-sa-associate-saac03/main/2100-IAC_CLOUDFORMATION/00_LEARNINGAIDS/TemplateParameters-1.png" width="750"/>
</p>
<p align="center">
  <img src="https://raw.githubusercontent.com/acantril/aws-sa-associate-saac03/main/2100-IAC_CLOUDFORMATION/00_LEARNINGAIDS/PseudoParameters-1.png" width="750"/>
</p>
<p>Parameters make templates reusable across environments.</p>
<pre><code class="language-yaml">Parameters:
  InstanceType:
    Type: String
    Default: t3.micro
    AllowedValues:
      - t3.micro
      - t3.small
      - t3.medium
    Description: EC2 instance type

  DBPassword:
    Type: String
    NoEcho: true          # ← Masks value in console and CLI output
    MinLength: 8
</code></pre>
<h3>Parameter Types</h3>
<table>
<thead>
<tr>
<th>Type</th>
<th>Description</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>String</code></td>
<td>Plain text value</td>
</tr>
<tr>
<td><code>Number</code></td>
<td>Integer or float</td>
</tr>
<tr>
<td><code>List&#x3C;Number></code></td>
<td>Comma-separated list of numbers</td>
</tr>
<tr>
<td><code>CommaDelimitedList</code></td>
<td>Comma-separated list of strings</td>
</tr>
<tr>
<td><code>AWS::EC2::KeyPair::KeyName</code></td>
<td>Validates key pair exists in the account</td>
</tr>
<tr>
<td><code>AWS::EC2::VPC::Id</code></td>
<td>Validates VPC ID exists</td>
</tr>
<tr>
<td><code>AWS::SSM::Parameter::Value&#x3C;String></code></td>
<td>Pulls value from SSM Parameter Store at deploy time</td>
</tr>
</tbody>
</table>

<p>💡 <strong>Exam Tip:</strong> Use <code>NoEcho: true</code> for sensitive parameters like passwords. The value is never shown in the console, CLI, or CloudFormation events.</p>
</blockquote>

<h2>🗺️ Mappings</h2>
<p align="center">
  <img src="https://raw.githubusercontent.com/acantril/aws-sa-associate-saac03/main/2100-IAC_CLOUDFORMATION/00_LEARNINGAIDS/CloudFormationMappings.png" width="750"/>
</p>
<p>Mappings are static lookup tables — great for region-to-AMI or environment-to-size mappings.</p>
<pre><code class="language-yaml">Mappings:
  EnvironmentConfig:
    prod:
      InstanceType: t3.large
      MultiAZ: true
    dev:
      InstanceType: t3.micro
      MultiAZ: false

Resources:
  MyInstance:
    Type: AWS::EC2::Instance
    Properties:
      InstanceType: !FindInMap [EnvironmentConfig, !Ref EnvironmentType, InstanceType]
</code></pre>
<hr>
<h2>🔀 Conditions</h2>
<p align="center">
  <img src="https://raw.githubusercontent.com/acantril/aws-sa-associate-saac03/main/2100-IAC_CLOUDFORMATION/00_LEARNINGAIDS/CloudFormationConditions.png" width="750"/>
</p>
<p>Conditions allow you to create resources or set property values based on logic.</p>
<pre><code class="language-yaml">Conditions:
  IsProd: !Equals [!Ref EnvironmentType, prod]
  IsNotProd: !Not [!Condition IsProd]

Resources:
  ProdOnlyBucket:
    Type: AWS::S3::Bucket
    Condition: IsProd          # ← Only created in prod

  MyInstance:
    Type: AWS::EC2::Instance
    Properties:
      InstanceType: !If [IsProd, t3.large, t3.micro]   # ← Conditional value
</code></pre>
<h3>Condition Functions</h3>
<table>
<thead>
<tr>
<th>Function</th>
<th>Description</th>
</tr>
</thead>
<tbody>

<td>True if two values are equal</td>
</tr>
<tr>
<td><code>!Not</code></td>
<td>Inverts a condition</td>
</tr>
<tr>
<td><code>!And</code></td>
<td>True if all conditions are true</td>
</tr>
<tr>
<td><code>!Or</code></td>
<td>True if any condition is true</td>
</tr>
<tr>
<td><code>!If</code></td>

</tr>
</tbody>
</table>

</tr>
<tr>
<td><code>!Cidr</code></td>

</tr>

<h2>📤 Outputs &#x26; Cross-Stack References</h2>
<p align="center">
  <img src="https://raw.githubusercontent.com/acantril/aws-sa-associate-saac03/main/2100-IAC_CLOUDFORMATION/00_LEARNINGAIDS/CloudFormationOutputs.png" width="750"/>
</p>
<p align="center">
  <img src="https://raw.githubusercontent.com/acantril/aws-sa-associate-saac03/main/2100-IAC_CLOUDFORMATION/00_LEARNINGAIDS/CloudFormationCrossStackReferences-1.png" width="750"/>
</p>
<p align="center">
  <img src="https://raw.githubusercontent.com/acantril/aws-sa-associate-saac03/main/2100-IAC_CLOUDFORMATION/00_LEARNINGAIDS/CloudFormationCrossStackReferences-2.png" width="750"/>
</p>
<p>Outputs expose values from a stack that can be consumed by other stacks or displayed in the console.</p>
<pre><code class="language-yaml">Outputs:
  VPCId:
    Description: "The VPC ID"
    Value: !Ref MyVPC
    Export:
      Name: !Sub "${AWS::StackName}-VPCId"   # ← Must be unique per region/account
</code></pre>
<p>Consuming stack:</p>
<pre><code class="language-yaml">Resources:
  MySubnet:
    Type: AWS::EC2::Subnet
    Properties:
      VpcId: !ImportValue "NetworkStack-VPCId"
</code></pre>
<blockquote>
<p>⚠️ <strong>Important:</strong> You cannot delete a stack that has exported outputs being consumed by another stack. Delete the consuming stack first.</p>
</blockquote>

<h2>🏗️ Nested Stacks</h2>
<p align="center">
  <img src="https://raw.githubusercontent.com/acantril/aws-sa-associate-saac03/main/2100-IAC_CLOUDFORMATION/00_LEARNINGAIDS/CloudFormationNestedStacks-1.png" width="750"/>
</p>
<p align="center">
  <img src="https://raw.githubusercontent.com/acantril/aws-sa-associate-saac03/main/2100-IAC_CLOUDFORMATION/00_LEARNINGAIDS/CloudFormationNestedStacks-2.png" width="750"/>
</p>
<p align="center">
  <img src="https://raw.githubusercontent.com/acantril/aws-sa-associate-saac03/main/2100-IAC_CLOUDFORMATION/00_LEARNINGAIDS/CloudFormationNestedStacks-3.png" width="750"/>
</p>
<p>Nested stacks allow you to break large templates into reusable modules.</p>
<pre><code>Root Stack (Master)
    ├── Network Stack (VPC, Subnets, IGW)
    ├── Security Stack (IAM Roles, Security Groups)
    └── Application Stack (EC2, RDS, ALB)
</code></pre>
<pre><code class="language-yaml">Resources:
  NetworkStack:
    Type: AWS::CloudFormation::Stack
    Properties:
      TemplateURL: https://s3.amazonaws.com/my-bucket/network.yaml
      Parameters:
        VPCCidr: 10.0.0.0/16
</code></pre>
<blockquote>
<p>💡 <strong>Exam Tip:</strong> Nested stacks are best for reusable components. Cross-stack references (Outputs + ImportValue) are best for sharing values between independently managed stacks.</p>
</blockquote>

<h2>🔍 Change Sets</h2>
<p align="center">
  <img src="https://raw.githubusercontent.com/acantril/aws-sa-associate-saac03/main/2100-IAC_CLOUDFORMATION/00_LEARNINGAIDS/CloudFormationChangeSets.png" width="750"/>
</p>
<p>Change Sets let you preview what will happen before executing a stack update — no surprises.</p>
<pre><code>Current Stack State  +  New Template  →  Change Set (Preview)  →  Execute
</code></pre>
<pre><code class="language-bash"># Create a change set
aws cloudformation create-change-set \
  --stack-name my-stack \
  --template-body file://updated-template.yaml \
  --change-set-name my-changes

# Review the change set
aws cloudformation describe-change-set \
  --stack-name my-stack \
  --change-set-name my-changes

# Execute if satisfied
aws cloudformation execute-change-set \
  --stack-name my-stack \
  --change-set-name my-changes
</code></pre>

<h2>🛡️ Stack Policies</h2>
<p>Stack policies protect critical resources from unintentional updates or replacements during stack updates.</p>
<pre><code class="language-json">{
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "Update:*",
      "Principal": "*",
      "Resource": "*"
    },
    {
      "Effect": "Deny",
      "Action": ["Update:Replace", "Update:Delete"],
      "Principal": "*",
      "Resource": "LogicalResourceId/ProductionDatabase"
    }
  ]
}
</code></pre>
<blockquote>
<p>⚠️ Once a stack policy is set, it cannot be deleted — only updated. All resources are protected by default if a policy exists with no explicit Allow.</p>
</blockquote>

<h2>🔄 Drift Detection</h2>

</code></pre>

aws cloudformation detect-stack-drift --stack-name my-stack

# Check drift results
aws cloudformation describe-stack-resource-drifts \
  --stack-name my-stack \
  --stack-resource-drift-status-filters MODIFIED DELETED
</code></pre>

<h2>🧩 Custom Resources</h2>
<p align="center">
  <img src="https://raw.githubusercontent.com/acantril/aws-sa-associate-saac03/main/2100-IAC_CLOUDFORMATION/00_LEARNINGAIDS/CloudFormationCustomResources.png" width="750"/>
</p>
<p>Custom Resources let you extend CloudFormation to manage resources it doesn't natively support — or run arbitrary logic during stack operations.</p>
<pre><code>CloudFormation Stack
        │
        │  Create/Update/Delete event
        ▼
  Lambda Function / SNS Topic
        │
        │  Performs custom logic
        ▼
  Sends response back to CloudFormation
  (Success or Failure + Data)
</code></pre>
<pre><code class="language-yaml">Resources:
  MyCustomResource:
    Type: Custom::MyLogic
    Properties:
      ServiceToken: !GetAtt MyLambdaFunction.Arn
      SomeInput: "value"
</code></pre>
<h3>Use Cases</h3>
<ul>
<li>Provision third-party resources (e.g., Datadog monitors, GitHub repos)</li>
<li>Run pre/post deployment scripts</li>
<li>Populate DynamoDB tables with seed data</li>
<li>Validate configurations before stack proceeds</li>
</ul>
<blockquote>
<p>💡 <strong>Exam Tip:</strong> Custom Resources must send a response back to a pre-signed S3 URL provided by CloudFormation. If the Lambda times out without responding, the stack will hang until the 1-hour timeout.</p>
</blockquote>

<h2>🏆 Golden Keypoints — Lessons from Production</h2>
<p>These are the kinds of lessons that don't usually appear in certification exams but make a huge difference when designing and operating production-grade cloud solutions.</p>
<hr>
<h3>🔹 CloudFormation can't be used with S3 presigned URLs as Template URLs</h3>
<p>CloudFormation needs to continuously access the template during stack operations — not just at the moment of submission. Temporary presigned URLs expire and can become inaccessible mid-operation, causing stack failures that are difficult to diagnose. Always use a <strong>permanent, publicly accessible S3 URL</strong> or a bucket policy that grants CloudFormation access to the object.</p>
<pre><code>❌ https://s3.amazonaws.com/bucket/template.yaml?X-Amz-Expires=3600&#x26;X-Amz-Signature=...
✅ https://s3.amazonaws.com/bucket/template.yaml  (with appropriate bucket/IAM policy)
</code></pre>
<hr>
<h3>🔹 CloudFormation can't create tags for resources it doesn't own</h3>
<p>CloudFormation can only manage the lifecycle of resources that are part of its own stack. If a resource was created outside of CloudFormation (manually, via CLI, or by another tool), CloudFormation has no authority to tag or modify it — even if you reference it in a template. For tagging external resources, use:</p>
<ul>
<li><strong>Custom Resources</strong> backed by Lambda to apply tags programmatically</li>
<li><strong>AWS Config + Automation</strong> to enforce tagging compliance</li>
<li><strong>Tag Editor</strong> in the AWS Console for one-time bulk tagging</li>
<li><strong>Automation scripts</strong> (CLI/SDK) as part of your deployment pipeline</li>
</ul>
<pre><code>✅ Resources CloudFormation created → CloudFormation can tag
❌ Pre-existing external resources  → CloudFormation cannot tag
</code></pre>
<hr>
<h3>🔹 CloudFormation template URL encoding for prefilled parameters</h3>
<p>When generating <strong>stack launch links</strong> with pre-populated parameters (e.g., a "Launch Stack" button in documentation or a portal), every parameter value in the URL must be properly URL-encoded. A single unencoded special character — a space, <code>+</code>, <code>=</code>, or <code>/</code> — silently breaks the parameter parsing and causes confusing deployment failures.</p>
<pre><code># Stack launch URL format
https://console.aws.amazon.com/cloudformation/home?region=us-east-1#/stacks/create/review
  ?templateURL=https%3A%2F%2Fs3.amazonaws.com%2Fbucket%2Ftemplate.yaml
  &#x26;param_EnvironmentType=prod
  &#x26;param_AppName=my%2Bapp%2Bname    ← URL-encode special characters
</code></pre>
<p>Always URL-encode parameter values when constructing launch links programmatically, and test the full URL end-to-end before publishing it.</p>
